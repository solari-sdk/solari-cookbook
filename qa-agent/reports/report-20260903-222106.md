**Sentinel:** The homepage loads the OWASP Juice Shop, a deliberately vulnerable application. The challenge is to perform a **DOM XSS** using the payload:

```html
<iframe src="javascript:alert(`xss`)">
```

---

### Hypothesis
DOM XSS occurs when user-supplied input is dynamically written to the DOM without proper sanitization, allowing arbitrary JavaScript execution. The payload above is a classic example of a DOM-based XSS vector that exploits the `javascript:` pseudo-protocol in an `<iframe>`'s `src` attribute.

---

### Recon Plan
1. **Identify input vectors**: The app has a search bar, language selector, and product pages. The search bar is the most likely candidate for DOM XSS, as it reflects user input directly into the DOM (e.g., "X results for 'query'").
2. **Test the search bar**: Inject the payload into the search field and observe if it is reflected in the DOM in a way that triggers the `javascript:` pseudo-protocol.
3. **Alternative vectors**: If search doesn't work, check other inputs (e.g., product reviews, URL parameters, or the language selector).
