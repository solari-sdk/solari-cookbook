# Completion guardian

**Authoritative source:** the active Forklift objective and the first three
project-ledger events. Build a competition-grade Solari submission that performs
a difficult real GUI business workflow transactionally, survives frozen hidden
cases and intentional faults, and accepts zero invalid business states inside a
precise rollback boundary. Public release remains user-controlled; product-
market fit requires real external reuse and is not part of the technical claim.

**Target capability:** let an unreliable visible-computer worker attempt a real
Odoo purchase-to-pay transaction while making only a semantically valid,
immutable result eligible to become durable.

**Method contract:** precommit cases, faults, oracle, expectations, resource
cap, and stop rules; preserve every attempt; compare a matched simpler baseline;
separate development from sealed evidence; inspect an immutable snapshot from a
fresh auditor; bind the verdict to case, fault, lineage, and exact snapshot; do
not call shared-workspace evidence independent replication.

**Current work and decision:** decide whether Forklift is a completed technical
submission artifact or still needs construction/evidence work.

**Causal bridge:** visible Odoo GUI attempt mutates one disposable branch → the
exact branch is snapshotted → a fresh restored database auditor checks purchase,
inventory, tax, payable, and payment invariants → only an all-pass, receipt- and
lineage-bound snapshot is selectable → live promotion closure proves that exact
snapshot can boot durably. This bridge would be false if the worker bypassed the
GUI, the auditor inspected mutable state, an invalid snapshot were selected, or
the promoted template differed on re-audit; current code and artifacts reject
all four counterexamples.

**Method verdict: pass.** The final-v2 seed, six positions, code/dependency
hashes, expected outcomes, zero-extra-dollar cap, retry boundary, and stop rules
were frozen before execution. All eight attempts were retained. Two pre-login
Chrome crashes were labeled infrastructure failures and retried only before
business mutation; there were zero post-mutation retries. The revealed seed,
cases, raw attempts, report, and 16-event hash-chained ledger verify. The matched
completion-signal baseline falsely accepted 3/16 audited developmental states;
Forklift falsely accepted 0. Claims remain at adversarial-verification level.

**Object verdict: pass.** Headful Chrome performed the real Odoo workflow. The
sealed campaign completed 6/6 hidden positions: four valid states accepted, two
invalid states refused, and zero invalid states accepted. Durable promotion was
booted and re-audited successfully. The local broken-versus-valid Odoo challenge
passes, and a clean 133-file public export reproduces the final verifier and all
69 tests without a key.

**Classification:** aligned completion for the active technical objective.

**Disproportion check:** further internal cases, ledgers, or evaluator work
cannot establish real demand or independent replication. More internal process
would now be drift.

**Recommendation:** close the technical build goal. Keep public publication,
Solari tagging, and external-user outreach pending explicit user authorization.
Do not claim product-market fit or independent replication until an actual
outside practitioner supplies that evidence.

**Work to discard or quarantine:** final-v1 remains retired unopened; its cases,
custody seed, and protocol stay ignored. Development scratch artifacts remain
separate from the sealed score.

**Resume condition:** reopen engineering only for a reproducible external
failure or a user-authorized new objective. External adoption work begins after
publication authority, not by manufacturing another internal “stranger” test.
