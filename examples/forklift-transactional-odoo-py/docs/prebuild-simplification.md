# Pre-build simplification fidelity card

## Protected claim

Zero invalid final Odoo states are accidentally accepted within the frozen VM,
case, fault, and oracle boundary. The design must also accept a useful fraction
of fault-free work so that "always reject" cannot win.

## Protected causal contrast

The same fallible GUI worker is unsafe when it mutates the only business state
directly, but safe to use as a proposal generator when mutations occur on
disposable branches and an independent semantic oracle controls promotion.

## Deleted before construction

- model ensembles and multi-agent voting;
- a dashboard, cinematic replay UI, and custom visualizations;
- blockchain, signatures, or cryptographic receipt infrastructure;
- a custom ERP or imitation business app;
- automatic natural-language invariant generation;
- external banking, email, and SaaS side effects; and
- repeated adaptive tuning on hidden final evidence.

## Reused rather than rebuilt

- Solari VM snapshot/copy/destroy primitives provide isolation and rollback;
- Odoo provides the real business UI and accounting/stock semantics;
- PostgreSQL is the ground-truth state inspected by the oracle; and
- Docker Compose supplies the local developmental twin.

## Minimal mechanism retained

One orchestrator, one deterministic GUI worker, one bounded fault injector, one
read-only oracle, and Solari's existing lifecycle primitives. Every retained
part changes either isolation, adversarial exposure, acceptance, or cleanup.

## What would falsify the simplification

If a single candidate plus one snapshot achieves the same measured safety and
useful acceptance rate under the same fault budget, branching is unnecessary
and must be removed. If database checks can be safely replaced by a smaller
oracle without accepting any seeded counterexample, the oracle must shrink.
